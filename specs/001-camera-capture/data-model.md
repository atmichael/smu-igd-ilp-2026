# Data Model: Camera Document Capture

Camera-session data is transient client state. It is not persisted before explicit submission. After submission, the source-document intake service owns the durable document and ordered page records.

## CaptureSession

Represents one user-initiated attempt to capture exactly one source document.

| Field | Type | Rules |
|---|---|---|
| `sessionId` | UUID | Generated by the client when capture starts; identifies only the in-memory session. |
| `state` | `CaptureState` | One of `idle`, `requestingPermission`, `liveCapture`, `pageReview`, `documentReview`, `submitting`, `submitted`, `recoverableError`, `cancelled`. |
| `pages` | ordered `CapturedPage[]` | Zero to three accepted pages; order is the order presented at final review. |
| `pendingPage` | `CapturedPage?` | At most one newly captured page awaiting accept, retake, or discard. |
| `errorCode` | string? | A user-safe camera or submission failure category; never contains image data. |

### State transitions

- `idle` -> `requestingPermission` after the user starts capture.
- `requestingPermission` -> `liveCapture` when a video-only stream is granted; otherwise -> `recoverableError`.
- `liveCapture` -> `pageReview` after a still frame is captured and all camera tracks are stopped.
- `pageReview` -> `documentReview` when the page is accepted, or -> `liveCapture` to retake/retry.
- `documentReview` -> `liveCapture` to add or retake a page while fewer than three pages are accepted; -> `submitting` only after explicit confirmation.
- `submitting` -> `submitted` on complete API acceptance; -> `recoverableError` on failure while keeping pages in memory for an explicit retry.
- Any pre-submission state -> `cancelled` on exit; discard all page blobs, revoke preview URLs, and stop any active tracks. Pre-existing application work is unaffected.

## CapturedPage

A still image captured during the active session.

| Field | Type | Rules |
|---|---|---|
| `pageId` | UUID | Client-generated identity for preview/list updates; not a durable document ID. |
| `position` | integer | One-based order, from 1 through 3; renumber after a removal. |
| `image` | JPEG `Blob` | Original captured page image for this feature; no OCR, enhancement, or PDF conversion. |
| `capturedAt` | timestamp | Client capture time for review/debugging; do not treat as a trusted audit timestamp. |
| `previewUrl` | object URL | Derived local preview only; revoke when the image is removed/replaced or session ends. |

A retake replaces the pending/rejected image and must not submit the rejected blob. A removal drops the page and compacts subsequent positions.

## SourceDocument

The durable result of one confirmed capture, created by the shared intake/storage service. Camera, file upload, and mailbox share this record; see the [shared intake contract](contracts/source-document-intake.md#channels).

| Field | Type | Rules |
|---|---|---|
| `sourceDocumentId` | UUID | Assigned by the server only after accepting the complete submission. |
| `channel` | enum | `camera-capture` for this feature; `file-upload` and `mailbox` are owned by Features 01 and 03. |
| `pages` | ordered image records | One to three original JPEG images in the order confirmed by the user. |
| `pageCount` | integer | Must equal the number of accepted pages and be in the range 1-3. |
| `status` | enum | `received` after successful intake; OCR and downstream states are outside this feature. |
| `receivedAt` | timestamp | Server time the submission was accepted. |
| `submittedBy` | string | Authenticated user name. |
| `mediaType` | string | `image/jpeg` for camera captures. |
| `contentHash` | string | `sha256:` hash over the accepted pages. |
| `storageLocation` | string | `protected://source-documents/{sourceDocumentId}`: where the original pages are kept in the protected content store (Feature 08). |

The record and its idempotency key are persisted, and the record and pages can be read back through `GET /api/source-documents/{id}` and `/pages/{n}` (see the [intake contract](contracts/source-document-intake.md#read-operations)). The shared evidence-storage feature owns storage locations, retrieval, and audit metadata. A failed or invalid submission must not create a partial `SourceDocument`.
